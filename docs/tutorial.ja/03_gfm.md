# 3. GFM の書き方

pfpdf の Markdown は GitHub Flavored Markdown（GFM）が基準です。GitHub で使える標準的な記法がそのまま使えます。このチュートリアルを PDF に変換すると、この章の見出しやリスト、表なども表示例になります。

## 3.1 見出しと段落

`#` から `######` までの Markdown 見出しが使えます。見出しには Markdown に現れる順に一意のアンカーが付き、6 階層すべてが目次に載ります。同名の見出しのアンカーには、末尾に `-2`、`-3` のような番号が付きます。HTML で直接書いた `h1` から `h6` は自動目次の対象ではなく、リンク先にする場合は `id` を明示します。

文書言語が日本語（`lang: ja` または省略時に日本語と推定）の場合、段落中の漢字・かな・和文約物に挟まれたソースの改行は表示上の空白になりません。強調やリンクをまたぐ折り返しにも対応します。空行による段落分け、英単語の境界、明示した空白、Markdown の強制改行は保持します。コードや数式の内容や、その前後の改行は変更しません。生の HTML を含む段落も対象外です。

## 3.2 強調

強調（*emphasis*）、強い強調（**strong emphasis**）、取り消し線（~~strikethrough~~）、強調の入れ子（***strong + emphasis***）が使えます。

### 日本語の強調

日本語の文中でも `**` はそのまま使えます。全角の句読点や括弧が隣接していても正しく変換されます。

- これは**重要**です。
- これは**「強調表示」**の例です。
- これは**重要な点。**続きのテキストも書けます。
- ここは**（重要事項）**です。

`<strong>` タグを書く必要はありません。まず `**` を使ってください。

### 和欧間の空き

日本語文書では、和文と欧文・数字の境界に CSS による表示上の空きを自動で入れます。明示した空白と約物は保持し、コード・数式は対象外です。

この空きは表示上のもので、URL やコピーされる DOM の文字列に空白は挿入しません。PDF からテキストを抽出するツールは、この空きを空白として復元することがあります。

`lang: en` など日本語以外では自動適用しません。独自の CSS で `text-autospace: no-autospace` を指定すると解除できます。`text-autospace` に対応しないブラウザーでは、空きなしで表示します。

## 3.3 リスト

入れ子のリスト、番号付きリスト、タスクリストが使えます。

- 果物
  - りんご
  - みかん
    1. 温州みかん
    2. ポンカン
- 野菜

- [x] 完了したタスク
- [ ] 未完了のタスク

## 3.4 表

表には、HTML を直接書くよりも GFM の表の記法を推奨します。列の揃えも指定できます。

| 項目 | 左揃え | 中央 | 右揃え |
|---|:---|:---:|---:|
| A | left | center | 100 |
| B | left | center | 2,000 |

## 3.5 リンクと画像

- インラインリンク: [Vivliostyle](https://vivliostyle.org/)
- 自動リンク: https://commonmark.org/ のように URL をそのまま書くとリンクになります
- 画像: `![代替テキスト](assets/example.svg)` のように相対パスで指定します

![サンプル画像](assets/example.svg)

### 長い URL と識別子

16 文字以上の URL、メールアドレス、パス、snake_case・kebab-case・camelCase の識別子には、表示時の改行候補が自動で入ります。文字数は、結合文字などを見た目の 1 文字にまとめる書記素クラスター単位で数えます。URL の `/` や `?`、ホスト名の `.`、識別子の区切りが優先されます。リンク先やコピーされる文字列に空白・ゼロ幅文字は追加されません。

https://example.invalid/reports/2026/very-long-document-name?format=print&language=ja

インラインコードとコードブロック、数式、`kbd`、`samp` の内容は、そのまま保つことを優先するため対象外です。コードの長い行は、テンプレートの既存の折り返し規則で表示されます。

## 3.6 引用とコード

> これは blockquote です。
> 複数行にわたって書けます。

インラインコードは、`` `backtick` `` のようにバッククォートで囲みます。コードブロックは 05 章を参照してください。

## 3.7 水平線

`---` または `***` で水平線（thematic break）になります。

---

字下げをせず、`_` を 3 個以上連続させただけの行（`___`、`____` など）は、pfpdf では改ページ（02 章参照）に予約されているため、水平線には使えません。引用やリストの内側、または `_` の前後や途中に空白がある場合は、改ページ記法として扱いません。

## 3.8 GFM に含まれない GitHub の機能

GitHub.com 上の一部の表示は GFM の仕様ではなく、GitHub のサービス固有の機能です。次は pfpdf では変換されません。

- `@user` のメンション、`#123` の Issue やプルリクエストへの参照
- `:smile:` のような絵文字のショートコード
- `> [!NOTE]` などのアラート

Mermaid は pfpdf の拡張機能として対応しています。フェンスによるコードブロックに `mermaid` を指定する記法は、05 章を参照してください。それ以外の機能が必要な場合は、生の HTML（04 章）や画像で表現してください。

## 3.9 BibTeX 参考文献

Markdown のフロントマターの `bibliography` で `.bib` ファイルを指定します。相対パスは、`bibliography` を最初に指定した Markdown ファイルの親ディレクトリーを基準にします。複数の `.bib` ファイルはリストで指定できます。複数の Markdown ファイルに指定があっても、最初の `bibliography` の値を採用し、リスト同士は結合しません。

```yaml
---
title: 調査報告
bibliography:
  - bibliography/references.bib
---
```

本文では、BibTeX のキーを TeX と同じ `\cite` コマンドで指定して文献を引用します。複数のキーはコンマで区切ります。

```md
先行研究\cite{smith2024}と比較研究\cite{smith2024,tanaka2025}を参照します。
```

引用は `[1]` のような番号になり、PDF 内の参考文献の項目へのリンクが付きます。参考文献一覧を置く場所には、文書の最上位の独立した行に `\printbibliography` を書きます。通常の Markdown 見出しを直前に書けば目次にも載ります。

```md
# 参考文献

\printbibliography
```

`\printbibliography` を省略した場合は、一覧を文書末尾へ追加します。インラインコード、コードブロック、生の HTML、数式内の `\cite` は文献引用として解釈しません。`\cite` 自体を表示する例は、`` `\cite{key}` `` のようにインラインコードで書けます。バックスラッシュでエスケープして表示する場合は `\\cite{key}` と書きます。

初期版は、BibTeX / BibLaTeX の `.bib` ファイルと、引用を番号で示す書式に対応しています。存在しないキーや重複するキー、不正な BibTeX、読み込めないファイルがあると、PDF を部分生成せず、終了コード `2` で失敗します。TeX の `\ref` は文献引用ではなく、将来の図表・数式・節参照用に予約しています。

## 3.10 脚注

脚注は、参照と定義を同じ Markdown ファイル内に書きます。

```md
本文です[^memo]。同じ脚注を再参照できます[^memo]。

[^memo]: 補足説明です。
```

各脚注の本文は、最初に参照したページの下部に表示されます。設定の追加は必要ありません。

脚注には、文書全体で最初に参照された順に番号が付きます。別のファイルでは同じ脚注識別子を再利用でき、それぞれ別の脚注になります。

同じ脚注を後のページで再参照した場合は、最初に表示した脚注へリンクし、本文を重複印刷しません。長い脚注は次のページへ続き、複数段落・コード・リンクも使えます。日本語文書では、参照・戻りリンクのアクセシビリティーラベルも日本語になります。
