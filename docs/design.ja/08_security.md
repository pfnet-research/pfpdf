# 8. セキュリティーモデル

## 8.1 信頼の前提

pfpdf は、生の HTML と利用者のスクリプトを処理できるローカルのビルドツールです。そのため、入力文書を信頼することを前提とします。不特定ユーザーの入力を処理する CI サービスとしての利用はサポートしません。

利用者向けの `SECURITY.md` には、少なくとも次を記載します。

- 信頼できない文書を実行しない
- Chromium が生の HTML やスクリプトを処理・実行し、外部 URL の参照先を取得することがある
- GitHub.com が HTML への変換後に行うサニタイズは行わず、GFM の Disallowed Raw HTML タグフィルターも自由度を優先して適用しない
- 生の HTML とカスタムテンプレートは、pfpdf のプロセスから参照できるローカルファイルを読み、その内容を外部のエンドポイントへ送信し得る。レンダラーは、信頼できない入力を隔離するサンドボックスではない
- 静的なローカルリソースの参照では、入力ルートだけを許可するリストによって `..`、絶対パス、シンボリックリンクの参照先を制限しない
- スクリプトが実行時に生成するローカルパスは静的リソースグラフの対象外であり、レンダラーで参照できることは保証しない
- ホストフォントの直接参照は再配布を避ける手段であり、利用権や PDF への埋め込み権を与えるものではない
- カスタムテンプレートとロゴは、利用者が権利と内容を確認した信頼済みの入力として扱う
- 脆弱性の非公開報告先
- サポート中のリリース系列

## 8.2 実装上の原則

- 子プロセスの起動に `shell: true` を使わない。シェルが解釈する文字列を組み立てず、引数配列で起動する
- テレメトリーやクラッシュレポートを外部へ送信せず、更新確認のための外部通信も行わない
- ブラウザーには、バージョンを固定した Vivliostyle CLI が標準で管理するものか、利用者がパスを明示したものを使う
- ループバックの `AssetServer` は `127.0.0.1` だけにバインドする。リソースマニフェストは、レンダラーに依存しない URL 解決に使い、ファイルアクセスを制限するセキュリティー境界としては扱わない
- フォントファイルの埋め込み制限を検出できた場合は無視せず、フォント名と対応方法を表示する
- 一時パスに予測可能な固定名を使わない
- ビルド用の作業ディレクトリーは利用者だけが読める権限で作る。最終出力と同じディレクトリーに置く一時ファイルは排他的に新規作成し、既存のシンボリックリンクやファイルを一時出力として再利用しない
- Chromium のサンドボックスを理由なく無効化しない
- ブラウザーの実行ファイルのキャッシュと実行時のプロファイルを分離し、利用者が既に使っているブラウザーのプロファイルや Cookie ストアを使わない
- ブラウザーのダウンロード、完全性の確認、キャッシュの展開は Vivliostyle CLI とブラウザーマネージャーの責務とし、pfpdf で重複実装しない
- 子プロセスは通常の CLI ツールと同様に、呼出元の環境変数を継承する。入力文書とカスタムテンプレートは、それらの環境変数を参照し得る信頼済みのコードとして扱う
- レンダラーの診断出力は改変せずに表示・保存する。入力由来の制御文字や、認証情報を含む URL をログに出したくない場合は、利用者が文書と実行環境を調整する
- YAML フロントマターは、既存の YAML ライブラリーの JSON スキーマを使ってマッピングとして読み、pfpdf が利用するメタデータフィールドの名前と型だけを検査する
- HTML、CSS、URL、OpenType は、それぞれ専用のパーサーでトークンやテーブルの境界に沿って処理する。正規表現で解析し直したり、未検証のオフセットから読み取ったりすることは避ける
- レンダラーの処理全体に期限を設け、タイムアウト後は子プロセスを回収し、サーバーの待ち受けを停止する。信頼済みの入力であっても、ブラウザーのダウンロード、スクリプトの実行、ブラウザーの動作が止まったまま無期限に待つことはしない

## 8.3 サンドボックスの位置付け

- pfpdf のローカルリソースグラフは、リソースの参照先を正しく解決するための仕組みであり、信頼できない入力に対するセキュリティー境界ではない
- 文書内の信頼済みスクリプトは、同一オリジンのリソースを読み、その内容を外部のエンドポイントへ送信し得る。そのため、`AssetServer` は機密性を保証しない
- Chromium のサンドボックスは多層防御として維持するが、それを根拠に信頼できない文書の処理を安全だと表現しない
- 外部リソースの取得結果は保証しない。再現性の確保や、ネットワークエラーと認証情報流出のリスクへの対応は利用者の責任であることを、README と `SECURITY.md` に明記する

## 8.4 Ubuntu のユーザー名前空間の制限

Ubuntu 23.10 以降では、ユーザー名前空間を特権なしで利用することに制限があります。そのため、共有ライブラリーが揃っていても Chromium のサンドボックスを起動できない場合があります。pfpdf はサンドボックスに起因する失敗を、ライブラリー不足による失敗と区別して診断します。

AppArmor プロファイルの追加など、root 権限での作業が必要な回避手順は、チュートリアルのトラブルシューティングの章に記載します。pfpdf 自身が root 権限で暗黙に設定を変更することはしません。
