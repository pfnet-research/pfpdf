# 7. 互換性とテスト

## 7.1 固定している依存関係と検証済み OS

この章には、現在固定している依存関係のバージョンと検証済み OS を記録し、リリースごとの完全な互換性表は作りません。正確なパッケージバージョンと整合性ハッシュは、ソースと CI では `package-lock.json`、公開する tarball では同じ依存ツリーから生成した `npm-shrinkwrap.json` を基準とします。利用者向けの対応範囲はこの章を基準とし、これらが一致しなければリリースを禁止します。

下表は依存関係の固定方法を示します。リリース候補では、各行に正確なバージョン、ブラウザーのリビジョン、OS イメージのバージョン、検証日を記入します。「現行」「最新版」「11 系」のような範囲だけで互換性を表明している場合は、リリースを禁止します。

| 項目 | 固定方法 | 備考 |
|---|---|---|
| Vivliostyle CLI | 直接依存の厳密なバージョン指定 + ソース側ロックファイル + 公開用 shrinkwrap | AGPL-3.0。更新は各対象 OS のサンプル PDF スモークテスト後に行う |
| ブラウザーのビルド | バージョンを固定した Vivliostyle CLI の標準機構（`@puppeteer/browsers`） | pfpdf は独自のダウンローダーを持たない |
| GFM パーサー | ソース側ロックファイル + 公開用 shrinkwrap | 版を固定した GFM Spec の適合性確認用の例で検証する |
| CJK 対応の拡張 | ソース側ロックファイル + 公開用 shrinkwrap | GFM の打消し線との組合せを確認する |
| PDF の解析・書換えライブラリー | ソース側ロックファイル + 公開用 shrinkwrap | 相互参照表（xref）・ページツリーの検査とメタデータの更新を全対象 OS で確認する |
| MathJax / highlight.js | パッケージに同梱する固定バージョン | CDN から取得しない |
| 標準フォント | パッケージに同梱 | 再配布可能な日本語フォント |
| Node.js の対応バージョン範囲（semver） | `package.json` の `engines` + 起動時検査 | バージョンを固定した直接依存の要件の共通部分に合わせる |

検証済み OS は次の 4 環境で、いずれも CI で実際のブラウザーによる PDF 生成まで確認します。

- macOS aarch64（主要サポート）
- Linux x86_64（主要サポート）
- Windows x86_64（追加サポート）
- Linux aarch64（追加サポート）

各アーキテクチャーでは、そのアーキテクチャー向けのブラウザー実行ファイルを実際に起動して検証します。x86_64 のエミュレーションで成功しただけでは arm64 対応としません。OS イメージやホスト型ランナーのラベルが更新された場合は、同じ名前でも実行環境が変わり得るため、検証日とイメージのバージョンを更新します。

## 7.2 Linux の実行環境の前提

Linux では、ブラウザーの配布アーカイブだけでは共有ライブラリーが揃いません。

- 対応ディストリビューションは GitHub ホスト型ランナーの Ubuntu と現行の Debian stable を最初の検証対象とし、必要な共有ライブラリーのパッケージを、バージョン管理する文書に記録して維持する
- `--doctor` で不足するライブラリーを可能な範囲で報告し、root 権限で自動的にインストールしない
- 共有ライブラリーが揃っていても、Ubuntu 23.10 以降の非特権ユーザー名前空間の制限のように、Chromium のサンドボックスを起動できない環境がある。サンドボックスに起因する失敗をライブラリー不足と区別して診断し、AppArmor プロファイルの追加など root 権限の作業を伴う回避手順は、チュートリアルのトラブルシューティング章に記載する

## 7.3 単体テスト

- pfpdf 固有の後処理を適用する前の `GfmAdapter` が、版を固定した GFM Spec の適合性確認用の例を通ること。ただし、Disallowed Raw HTML のタグフィルターについては、仕様に記録した意図的な差を認める
- 見出し、リスト・入れ子のリスト・タスクリスト、引用、コード、リンク・画像・自動リンク、強調・強い強調、打消し線、表、生の HTML など、GFM の各構文を変換できること
- CJK 対応の強い強調について、`これは**重要**です`、`これは**「強調表示」**の例です`、`これは**重要な点。**続き`、全角括弧、ASCII / CJK の混在、入れ子の強調、3 個以上の `*` を含む正常系を検査する
- CJK 対応の拡張が、コードスパン、フェンスによるコードブロック、生の HTML、リンク先の URL、数式、エスケープ済みの `\**`、対応しない片側だけの `**` を書き換えないこと
- CJK 対応の拡張を適用した後も、版を固定した CommonMark / GFM の既存フィクスチャーに意図しない差がないこと
- インライン・ブロックの生の HTML、`style` / `script`、文書を制御する要素、独自属性を、信頼済みの入力として保持すること
- 単独行の `___` が改ページになり、GFM の区切り線には `---` / `***` が使えること
- フロントマターの正常系・異常系を検査する。各ファイルのメタデータを本文から除去し、キーごとの先勝ちで値を選び、後続ファイルから未設定値を補完すること。相対パスを選択元のファイルを基準に解決し、リスト全体を一つの値として選び、不採用のアセットを読み込まないこと。全ファイルを検証し、元の行番号を保持すること
- タイトル内の許可された改行、シリーズ名の指定・省略、正のページサイズ、BCP 47 言語タグの明示値の優先と省略時の日英推定、`dir` の `ltr` / `rtl` / `auto` と既定値 `auto`、先頭の言語サブタグに応じた固定の日付表示を検査する
- YAML のマッピングと、利用するメタデータフィールドの型を検査する
- 未知のフロントマターキーは既定で警告して無視し、`--strict-front-matter` では拒否すること。既知キーの不正値、重複キー、不正な YAML は、厳格モードの有無にかかわらず拒否すること。通常変換、設定表示、`--doctor` での一貫性、標準エラーの警告と標準出力の JSON の分離、CLI の優先順位、厳格モードの失敗時に既存 PDF を保持することを検査する
- タイトル未指定時の H1・入力名からの補完と明示値の優先を検査する。空・入れ子の H1、文字参照を一度だけ解決すること、日本語ファイル名、本文見出しの保持、表紙と PDF メタデータの一致、表紙省略時のタイトル補完も検査する
- UTF-8 BOM と CRLF の受入れ、不正な UTF-8 の拒否、ロケールに依存しないファイル名のソートを検査する
- 標準入力・標準出力を表す `-` を入力・出力に指定した場合は拒否すること
- 各 Markdown ファイルを独立して解析し、未閉鎖のフェンス、HTML ブロック、リスト、Setext 見出し、参照リンクの定義が次のファイルへ影響しないこと
- 見出しのスラッグに含まれる Unicode、記号だけの見出し、`x` / `x-2` の衝突を検査する。生の HTML の見出しを自動目次の対象にせず、重複見出しにも一意なアンカーを割り当て、同一文書に含まれる Markdown ファイルへのリンクを書き換えること
- 行内数式・別行立て数式の区切りの境界、内部の `*` / `_`、通貨表記、エスケープ、閉じていない区切りを検査する。長い `$` の列も線形時間で処理を終えること
- MathJax で、利用者の TeX の誤りをソース位置付きの終了コード `2`、同梱機能の初期化失敗を終了コード `1` に分類すること
- `___` の字下げ、引用・リスト内、`_` が 4 個以上、前後の空白、文書の先頭・末尾・連続といった境界条件を検査し、次のブロックへの `break-before` として正規化すること
- CLI の終了コード `0` / `1` / `2` と、標準出力・標準エラーの分離を検査する
- 改行、ESC、C0 / C1、双方向テキストの書式制御文字を含むパス・URL の診断を検査する。人が読む診断は改変せず、JSON ではシリアライザーの通常のエスケープを使うこと。不正な UTF-8 のファイル名は入力エラーにすること
- Node.js の対応バージョン範囲（semver）の内外の境界で、起動時検査が働くこと
- 正常終了、通常エラー、捕捉可能な中断で、ビルド用の作業ディレクトリーを削除すること
- `template` / `toc` / `cover` / `logo` の既定値、フロントマター、CLI の優先順位を検査する。CLI が常に優先され、不正なフロントマター値は上書きされる場合も拒否すること
- 排他的なフラグの同時指定、`--font-dir` 以外のオプションの重複、未知のオプション・位置引数・値の欠落、タイムアウト値の最小・最大・オーバーフローを検査する
- 同梱・カスタムテンプレートの必要ファイルと、ロゴ省略時の出力を検査する
- カスタムテンプレートの必須・重複・未知の DOM スロット、メタデータのテキスト挿入、未指定の `author` / `series` スロットの削除、タイトルで許可したタグ以外の拒否、ロゴ指定時にスロットがない場合の拒否を検査する
- 信頼済みの属性を保持し、処理した `data-pfpdf-slot` が残らないこと
- ホストのフォントが既定で無効であり、明示的に指定したフォントディレクトリーを利用できること
- フォント探索の決定的な優先順位、シンボリックリンクの循環、壊れた OpenType のオフセット・長さ、テーブル数・フェイス数の 4096 境界、重複フェイス、CSS のエスケープを検査する。`--font-dir` と CSS の直接 URL・`data:` フォントに対する埋め込み禁止フラグの扱い、カスタム CSS の `local()` に対する警告、同梱 CSS の `local()` 禁止も検査する
- 子プロセスの引数列・環境変数の上限、可変長の Unicode パス・プロキシー・カスタム CA を検査する。利用者に起因する誤りを終了コード `2`、同梱機能に起因する誤りを終了コード `1` に分類すること
- `SOURCE_DATE_EPOCH` と、PDF Info / XMP のタイトル・著者・言語・タイムスタンプの方針、カタログの `/Lang` を検査する。フロントマターの `date` があっても、`SOURCE_DATE_EPOCH` が未設定なら再現性の警告を出すこと
- `SOURCE_DATE_EPOCH` の負数、符号、空白、指数表記、安全な整数・Date の範囲を超える値を拒否すること
- PDF のヘッダー・EOF マーカー、xref・オブジェクトのオフセット・増分更新・カタログ・ページツリーを検査する。暗号化された PDF、0 ページの PDF、途中で切れた PDF は出力として確定しないこと。出力先のシンボリックリンクは参照先へ書き込まずに置換し、ディレクトリーは拒否すること
- `bibliography` の文字列・リスト、フロントマターを記したファイルを基準にする相対パス、絶対パス・`..`・シンボリックリンクを検査する。ファイルの欠落、ディレクトリー、NUL、不正な拡張子、不正な UTF-8 も検査する
- `\cite` の単一・複数・反復キー、日本語との隣接、`\\cite` のエスケープ、コード・生の HTML・数式の除外、見出し・リンク内での拒否を検査する。波括弧・キー・引用のまとまり（クラスター）の誤りには `file:line` 形式の診断を出すこと
- BibTeX / BibLaTeX の主要な文献種別、Unicode、波括弧による保護、アクセント、`@string`、crossref、同一・複数ファイル内の重複キー、引用したキーの欠落、未使用の文献の除外を検査する
- 引用・参考文献一覧・戻りリンクの `role`、生成する全 ID の一意性、生の HTML・テンプレートの ID との衝突、マーカーが 0 / 1 / 2 個の場合、同一の citeproc セッションに基づく番号と文献順を検査する

## 7.4 統合テスト

- `make docs-release` が `default` テンプレートで公開用文書を生成し、`make docs-templates` がマニフェストにあるすべての同梱テンプレートで共通サンプルを生成する。サンプルは `compact` で 4 ページ以上、その他で 5 ページ以上とし、ページ数に上限を設けない。`compact` 以外の目次は 2 ページ以上とし、サンプルに長い表・コードブロック、数式、画像、生の HTML、改ページを含める。`compact` では 2 段組みの目次と本文を最初のページに共存させる。`make docs-template-images` はレビュー用に全ページを連番の PNG 画像へ変換する。公開用文書、プレビュー PDF、確認画像は、出力ディレクトリーツリーと CI の成果物をそれぞれ分ける
- 単一の Markdown ファイルから `document.html` を生成し、テストが検査した同じファイルを Vivliostyle CLI が入力として使う
- ディレクトリー内の Markdown がファイル名順に結合される
- 各ファイルのブロック構文が隣接ファイルの内容に影響されず、ファイルごとのアンカーと文書全体で一意な見出しアンカーが生成される
- 表、タスクリスト、入れ子のリスト、打消し線、自動リンク、CJK 対応の強い強調を含む、GFM 構文を網羅した文書を HTML / PDF へ変換できる
- 共通プレビューの BibTeX による引用を、複数のクラスター、長い DOI / URL、CJK・ラテン文字の文献で検査する。すべての同梱テンプレートで欠落・はみ出しを起こさず、PDF 内部リンクとテキストの抽出を維持すること
- Markdown とインライン・ブロックの生の HTML を同じ文書で組み合わせ、HTML 要素、スタイル、必要なスクリプトが生成 HTML / PDF の双方へ反映される
- 相対パスの画像、空白を含むパス、日本語パスを処理できる
- `..`、絶対パス、シンボリックリンクの参照先を含む信頼済みのローカルリソースを、プロセスの権限内で参照できる
- 入れ子の CSS の `@import` / `url()`、インポートの循環、生の HTML の `srcset` / インラインスタイルをリソースグラフに取り込み、論理 URL でリソースを読める
- 取得用・移動用 URL について、相対 URL、`file:`、HTTP(S)、ネットワークパス参照、`data:`、`blob:`、`mailto:`、`tel:`、`javascript:`、未知のスキームの分類を検査する。生の HTML の `a[href]` でも、同一文書に含まれる Markdown ファイルへのリンクを書き換える。未解決のフラグメント、結合対象にない Markdown ファイルへのリンク、クエリーを持つ相対リンクなど、その他の移動用リンクは保持する
- スクリプトが動的に組み立てるローカルパスを、保証対象の静的リソースとして誤って成功扱いしない
- インラインのモジュールスクリプトと `iframe[srcdoc]` を信頼済み HTML として保持し、その内部のリソースグラフは追跡しない
- ループバックサーバーで、未知の ID、パストラバーサル、二重エンコーディング、不正な範囲指定を検査する。`GET` / `HEAD`、単一範囲のリクエスト、`Cache-Control: no-store` を扱い、終了後にポートを閉じる。事前検査後にシンボリックリンクや FIFO へ差し替えられても、特殊ファイルを読まずに失敗することを確認する
- DOM の解析、ローカルのスタイルシート・スクリプトの読み込み、フォントの準備、画像のデコード、数式の描画、コードハイライトが完了した後にページ分割が始まることを、バージョンを固定した Vivliostyle CLI と実際のブラウザーで検査する。準備完了まで文書の読み込みを保留する仕組みが解除される前に、ページ分割が始まらないこと。ローカルリソースのエラー、同梱スクリプトのエラー、登録した Promise の拒否、登録期限を過ぎた登録、完了通知の不整合は、上流の子プロセスの終了コードにかかわらず終了コード `1` にする
- 描画開始の準備が完了しない場合や、スクリプト・子プロセスが停止した場合も、全体に適用する期限までに終了させる。通常の終了要求と強制終了による後始末を行い、既存出力を保持する
- 読み取り専用の入力ディレクトリーから出力できる
- 既存出力がある状態でビルドに失敗しても既存出力を保持する
- 最終出力と同じディレクトリーに一時ファイルを排他的に作成し、成功後に出力として確定する。コピー元のサイズとコピーしたバイト数の不一致、コピー後の切断や xref・ページツリーの破損、PDF メタデータの更新後の破損、名前変更の失敗、一時ファイルの同期失敗、中断を意図的に発生させ、既存出力を保持することを検査する。確定後に親ディレクトリーの同期に失敗した場合は、永続性に関する警告を出すことも検査する
- 出力確定のクリティカルセクションの直前・実行中・名前変更の直後にシグナルを送り込む。確定前のシグナルでは終了コードを非 `0` にして既存出力を保持し、名前変更後は完全な新出力を残して終了コード `0` にすること
- PDF ワーカーを停止させる循環オブジェクト・巨大な xref のフィクスチャーでも、メインプロセスの期限とシグナル処理が働くこと。ワーカーを終了させ、最終出力と同じディレクトリーに作った一時ファイルを回収すること
- 同じ出力先を指定した 2 つのビルドを意図的に競合させてもバイト列が混在せず、最後に確定した完全な PDF だけが残る
- `npm pack` した tarball を、新しい一時プロジェクトから `npm exec` で実行できる
- ブラウザーがない初回実行では、バージョンを固定した Vivliostyle CLI の標準取得処理が動作するか、上流の診断をそのまま利用者へ示す
- `--browser-path` で明示した互換ブラウザーを利用できる
- フロントマターで `template`、`toc`、`cover`、`logo` を設定でき、CLI 引数が常に上書きする
- 現在の pfpdf のバージョンに対応するカスタムテンプレートのディレクトリーを利用できる
- ホストのフォントが無効なときは、OS のフォントディレクトリーを読み込まない
- 横書き RTL と縦書きのフィクスチャーで、ルートの `dir`、計算済みの書字モード、上流が生成する PDF の読み方向の組合せを確認する
- 同じ HTML のバイト列でもビルドごとにオリジン・ポートが異なることを検査する。生成 HTML に接続先のポートを埋め込まず、利用者スクリプトが `location` に依存する場合は再現性の保証対象外であることを確認する
- `--doctor` と `--print-effective-config` が、PDF を生成せずに診断結果を返す
- `--doctor` と `--print-effective-config` の標準出力を、各スキーマに従う JSON オブジェクト 1 個として解析できる。標準エラーのログを混ぜず、表示対象外のプロキシー URL やカスタム CA の内容を含めない
- `--doctor` がブラウザー検査用の一時プロファイルを安全に作成し、正常時・失敗時・タイムアウト時に回収する。プロジェクト・出力ディレクトリー、ブラウザーのキャッシュ、OS 設定を変更しない
- 子プロセスの出力・レンダラーの診断で、UTF-8 のコードポイントがチャンク境界をまたいでも正しくデコードする。診断内容は無害化や秘密情報の削除をせず、保持した作業ディレクトリーにもそのまま残す
- 子プロセスの出力が 8 MiB を超えても、パイプを読み取り続けて処理を止めない。保存する診断情報だけを上限で切り詰め、省略したバイト数を正しく記録する
- `docs/design.ja/` と `docs/design.en/`、`docs/tutorial.ja/` と `docs/tutorial.en/` のファイル集合・番号・相対パスが一致する
- 日英 4 文書を、リポジトリーの現在の pfpdf ビルドで生成できる

## 7.5 PDF スモークテスト

4 つの対応環境すべてで実際に Chromium を起動します。検査は、空ファイルや壊れた PDF を成功扱いしないための最小限に留めます。

- 出力が `%PDF-` で始まる
- ファイルが空でなく、`pdfinfo` で 1 ページ以上と確認できる
- `pdftotext` でタイトル、本文、日本語の代表文字列を確認する
- 日英の設計書・チュートリアルの 4 PDF について、タイトル、言語ごとの代表文字列、ページ数が 0 でないことを確認する
- チュートリアルの PDF で、表、日本語の強い強調、生の HTML、数式、コードハイライトの代表文字列を確認する
- 同梱する日本語フォントを使う基準フィクスチャーは、意図したフォントが埋め込まれ、サブセット化され、ホストのフォントへ置換されていないことを、4 環境で `pdffonts` により確認する。ホストのフォントを使う機能は、再配布可能な専用フィクスチャーで許可・拒否のフラグと実際に選択されたフォントを検査する
- PDF のバイト列の比較、全ページの画像化、一般文書の全フォントに対する完全なサブセット検査は必須にしない

通常実行の構造検査とは独立に、スモークテストでも `pdfinfo` の終了コードを検査し、xref が途中で切れた PDF、0 ページの PDF、暗号化された出力、解析不能な出力を成功扱いしません。`pdftotext` で代表文字列が見つからなければ、コマンド自体が終了コード `0` を返してもテストを失敗させます。

## 7.6 npm パッケージのテスト

- `npm ci` / `npm test` / `npm run lint` を実行する
- `npm pack --dry-run` で不要ファイルや秘密情報が含まれないことを確認する
- 梱包した tarball を使って `npm exec --package=<tarball> -- pfpdf --help` を実行する
- tarball に `npm-shrinkwrap.json` が含まれ、`package-lock.json` は含まれないことを確認する。空のプロジェクトへインストールした実行時の依存ツリーと整合性ハッシュが、ソース側ロックファイルと一致することを 4 環境で確認する
- 対応範囲の最古の Node.js で、梱包したエントリーポイントを読み込んで実行できること。対応範囲のすぐ外の代表バージョンでは、起動時検査が意図した診断を返すこと
- 4 つの対応環境で `tests/fixtures/minimal/` の PDF を生成する

## 7.7 プロパティーベーステスト・ファジング・性能テスト

- フロントマター、URL、HTML / CSS のリソーストークン、見出し、CJK の区切り文字、OpenType テーブルのパーサーにはプロパティーベーステストを用意する。任意のバイト列を与えても異常終了や応答停止を起こさず、入力エラーか正常な結果のどちらかを返すこと
- パスのテストでは、POSIX と Windows の区切り文字、ドライブ文字、UNC、予約名、末尾のドット・空白、Unicode 正規化を、プラットフォームごとのフィクスチャーで扱う。実行中の OS のパスライブラリーだけを使って、別 OS の文字列を誤って正規化しない
- `M`、`B`、`N`、`T`、`R`、`C`、`A`、`F`、`G`、`P` を個別に段階的に増やし、実経過時間、ピーク RSS、内部カウンターを記録する。カウンターでは、AST の訪問回数、マップの検索回数、ファイルの解析回数、ファイル名の比較回数、比較したバイト数、実際に配信したバイト数、コピーしたバイト数を数え、設計上の上限をアサーションで検査する。ソートと外部パーサー・レンダラーを除く線形処理は、専用ランナーで大きな入力を 3 点以上測定し、入力を 2 倍にしたときの時間・RSS の中央値が連続して 3 倍を超えた場合を性能劣化とする。バージョンを固定した GFM パーサーと実際のレンダラーは別系列で測定し、意図的に負荷を高めた入力に対する時間の推移とタイムアウトを記録する
- 長い区切り文字列、深く入れ子になったリスト・引用、CSS のインポートの循環、同名の見出し、多数の未解決リンク、多数のフォントフェイスを、意図的に負荷を高めるフィクスチャーとする
- ファジング用の入力集合で異常終了、タイムアウト、過剰なメモリー使用が見つかった場合は、原因を再現できる最小限の入力に絞り、通常のフィクスチャーに追加して再発を防ぐ
