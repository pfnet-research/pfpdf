# 5. レンダラー

## 5.1 `Renderer` インターフェース

`Renderer` インターフェースは、変更不可の `RenderJob` を受け取ります。`RenderJob` は生成済みの `document.html`、リソースマニフェスト、出力用の一時パス、一時的な作業ディレクトリー、解決済みの設定、絶対時刻で表した期限、`AbortSignal` を持ちます。レンダラーは `HtmlDocumentBuilder` が作った HTML のバイト列を `AssetServer` から取得し、Markdown の変換や設定解決を繰り返しません。

- レンダラーは成功時に出力パス、バイト数、経過時間を返し、失敗時に部分出力を結果オブジェクトとして返さない
- レンダラーが最初の外部プロセスを起動する直前に、その時点から既定で 300 秒後の時刻を期限として設定する。ブラウザーの確認と取得、描画開始の準備完了待ち、描画、PDF メタデータの後処理、構造検査に共通の期限を適用する。処理段階や子プロセスごとにタイムアウトを再設定して総時間が無制限に伸びないよう、すべての待機へ残り時間を渡す
- CLI と文書変換処理にはレンダラーの選択を公開せず、単一の描画経路を使う

## 5.2 Vivliostyle レンダラー

- Vivliostyle CLI は Node.js の子プロセスとして呼び出し、pfpdf 本体との境界を明確にする
- `AssetServer` の文書 URL を入力として渡し、作業ディレクトリーの `file:` URL を別に生成しない
- Vivliostyle CLI を `PATH` や `npx` で解決せず、pfpdf がパッケージの解決処理で特定したエントリーポイントを、`process.execPath` が指す Node.js で起動する
- バージョンを固定した Vivliostyle CLI が標準で管理するブラウザー、または利用者が明示した検証済みのブラウザーを使い、確認済みのオプション名を渡す。ブラウザーの取得やキャッシュの復旧は pfpdf で再実装しない
- シェル文字列を組み立てず、引数配列と `shell: false` で子プロセスを起動する
- 上流が提供するサンドボックスを不必要に無効化しない
- 子プロセスの stdout / stderr は親プロセスの stdout へ転送せず、必要なログレベルでは stderr へ逐次転送し、レンダラーの診断情報に保存する。信頼済みの入力を前提とするため、内容を無害化したり認証情報を伏せたりしない
- 保存するレンダラーの診断情報は 8 MiB を上限とし、超過後も子プロセスのパイプを読み続けてデッドロックを防ぐ。診断ファイルには切り捨てた旨と省略したバイト数を記録し、ログ量に比例してプロセスのメモリー使用量を増やさない。stderr への転送量自体は呼び出し側が管理し、stdout へ迂回しない
- タイムアウト、`SIGINT`、`SIGTERM` では新しい処理を開始せず、まず通常の終了処理を要求し、5 秒後に強制終了する。後片付け全体にも 15 秒の上限を持たせる。POSIX では専用のプロセスグループ、Windows では利用可能なプロセスツリーの終了機能を使って、ブラウザーの子孫プロセスも可能な限り回収する。上限後も OS が終了を確認できない PID は診断へ明記し、成功扱いしない
- ブラウザーの実行ファイルが存在するか、通常ファイルか、実行できるかを変換前に検査する。最小 HTML を使う追加の起動検査は毎回ではなく `--doctor` で行う。実際の変換でブラウザーとの非互換が判明した場合は、明確な診断を出し、終了コード `1` とする
- 子プロセスがシグナルで終了した場合、終了コードが `0` 以外の場合、期限後もパイプが閉じないかプロセスが終了しない場合は、成功にしない

## 5.3 出力の検証と確定

レンダラーは直接起動した子プロセスの終了を待ち、捕捉可能な中断時にはその子プロセスを停止します。入力サイズとリクエスト数に任意の固定上限は設けませんが、PDF の構造検査までの実行時間は `--render-timeout-ms` で制限します。

- 子プロセスが終了コード `0` を返した後、レンダラーの出力がシンボリックリンクではなく通常ファイルであり、少なくともヘッダーとトレーラーを保持できる長さを持つことを確認する
- `OutputCommitter` は、最終出力と同じディレクトリーに一時ファイルを排他的に作成しておく。レンダラーの出力を固定長バッファーでこの一時ファイルへコピーし、読み取り・書き込みの累計バイト数が、コピー元の検査済みサイズと一致することを確認する
- コピー後の一時ファイルの先頭と末尾を、それぞれ固定長で事前検査する。先頭には `%PDF-1.` または `%PDF-2.` ヘッダーがあり、末尾には最後の `%%EOF` マーカーがあり、その後は許可された空白文字だけであることを確認する
- PDF の構造を認識するライブラリーのバージョンを固定し、xref テーブル / ストリームと増分更新の連鎖、トレーラー / カタログ、オブジェクトのオフセット、ページツリーを構文解析する。修復モードや警告なしで 1 ページ以上を読めることを必須とする。暗号化された出力、存在しないオブジェクトへの参照、循環参照・範囲外参照、0 ページは終了コード `1` とし、ヘッダー / EOF だけが正しい壊れた PDF を出力として確定しない
- PDF Info / XMP のタイトル・著者・タイムスタンプとカタログの `/Lang` の後処理が必要な場合は、同じライブラリーの正式 API で一時ファイルを更新し、更新後の最終バイト列をもう一度構造検査する。バイト列の正規表現置換や、パーサーが自動修復した結果を成功出力に使わない
- PDF の構文解析や書き換えは、メインのイベントループを占有する同期処理として実行せず、終了可能なワーカースレッド、またはシェルを介さない専用の子プロセスに分離する。期限までの残り時間を渡し、タイムアウトや異常終了ではスレッドまたは子プロセスを終了して一時ファイルを破棄する。循環するオブジェクトグラフや巨大な xref によって、期限を監視するタイマーやシグナルハンドラー自体が動作できなくなる構成にしない
- 最終出力と同じディレクトリーの一時ファイルをフラッシュして閉じてから、02 章の順序で作業ディレクトリーの後片付けと最終パスへの出力確定を行う
- 実際に選ばれたフォント、テキストの内容、画像の差分までは通常実行で検査せず、CI で独立した `pdfinfo` / `pdftotext` / `pdffonts` を使うスモークテストで補う
- 生成に失敗した場合は既存出力を維持する
