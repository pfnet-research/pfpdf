2. 文書の構成

2.1 フロントマター

文書のメタデータや設定は、Markdown ファイルの先頭に YAML のフロントマターとして書きます。複数ファイルでは、キーごとに最初に書かれた値を使います。

---
title: 四半期報告書
author: 山田 太郎
series: 技術報告シリーズ
template: pfn
toc: true
cover: true
logo: assets/logo.svg
date: 2026-08-01
page_size: A4
confidential: false
lang: ja
dir: ltr
---

フロントマターで指定できるメタデータ 8 項目と、文書設定の template / toc / cover / logo を次の表に示します。第 3 章で説明する bibliography も、ビルドの入力として指定できます。その他のキーは、既定では標準エラー出力（stderr）に警告を出して無視します。キーの重複、不正な YAML、既知のキーの型や値の誤りはエラーです。

たとえば、他のツール用の tags や status を残したまま PDF 化できます。page_szie のような誤記も警告されるため、意図した設定が反映されたか確認してください。未知のキーをエラーにしたい場合は、CLI の --strict-front-matter を指定します。

npx @pfnet-research/pfpdf@latest --input docs --output docs.pdf --strict-front-matter

未知のキーへの警告や厳格な検証は、--print-effective-config --input docs と --doctor --input docs にも適用されます。--strict-front-matter は実行時の設定なので、フロントマターでは指定できません。

キー型既定値説明
title文字列H1、なければ入力名から補完文書タイトル。明示した値では <br> で改行できます
author文字列なし著者名
series文字列なしシリーズ名。すべての同梱テンプレートで、主要なラベルとして表示します
template同梱テンプレート名default文書に使用する同梱テンプレート
toc真偽値true目次を生成するかどうか
cover真偽値true表紙または先頭の文書ヘッダーを表示するかどうか
logoパスの文字列 / falseテンプレートの既定値表紙ロゴ。false ならロゴを表示しません
date文字列実行日表紙に表示する日付
page_sizeキーワード / 寸法A4ページサイズ
confidential真偽値falsetrue のとき全ページに Confidential を表示します
lang文字列（BCP 47 言語タグ）本文から ja / en を推定文書の言語。HTML の lang、組版、フォント選択に使います
dirltr / rtl / autoauto文書の文字方向。HTML のルート要素の dir に使います

  • タイトルの優先順位は --title → 入力順で最初に指定されたフロントマターの title → 入力順で最初に見つかる空でないトップレベル H1 → 入力名です。H1 は # 見出し と Setext 形式を対象とし、引用・リスト・コード・生の HTML ブロック・脚注定義の内側は使いません。本文の見出しは残ります

  • H1 の装飾は外し、リンクの表示文字列、コードや数式のソース、画像の代替テキストを使って 1 行にします。H1 がなければ、単一ファイルの入力では .md を除いたファイル名、ディレクトリー入力ではディレクトリー名を使います。入力名が空か、空白や改行しかない場合は document を使います。補完値の <br> や文字参照は再解釈しません

  • title に空文字列、不正な型の値、許可されない HTML を指定すると、入力エラー（終了コード 2）になります。補完や CLI の上書きがある場合も同じです

  • フロントマターの template には academic / book / compact / default / notebook / pfn / technical のいずれかを指定します。CLI の --template / --template-preset はフロントマターを上書きします

  • logo の相対パスは、フロントマターを書いた Markdown の親ディレクトリーが基準です。フロントマターではローカルファイルだけを指定でき、Git リポジトリーから取得するロゴは --logo で指定します

  • series を省略すると、シリーズの表示領域が削除されます。同梱テンプレートは固定の出版名、文書種別、ブランド名、定型ラベルを補いません

  • 表紙のタイトルを改行したいときは title: "長いタイトル<br>サブタイトル" のように <br> を使います。使える HTML 要素は、<br> / <br/> / <BR /> などの属性のない br 要素だけです

  • フロントマターは YAML のマッピングとして読みます。pfpdf が利用するのは上表の項目と第 3 章で説明する bibliography だけです。各キーの値は、表に記載した型で指定してください。複雑な YAML 値を書けても、メタデータとしては利用されません

  • 入力ファイルの最初の行が --- ならフロントマターの開始区切りとみなし、同じファイル内に閉じる区切りの --- または ... が必要です。各ファイルのフロントマターは本文から除去されます。各ファイルの先頭で水平線を出したい場合は *** を使ってください

  • page_size のキーワードは A3 / A4 / A5、JIS-B4 / JIS-B5、ISO-B4 / ISO-B5、Letter / Legal です。規格が曖昧な B4 / B5 は使えません。210mm 297mm のように幅と高さを指定することもできます

  • lang: en / lang: ja-JP のように明示した BCP 47 言語タグが最優先です。省略時は全入力ファイルの本文から日英を推定し、実行環境のロケールは使いません。かな・漢字・英字を数え、次のいずれかを満たす場合は ja、それ以外は en です

    • ひらがなが 2 字以上あり、対象文字の 1% 以上を占める
    • かなを含み、かなと漢字の合計が英字数以上である
    • 漢字数が英字数を超える

    コード・数式・生の HTML ブロック・URL は判定から除外します。判定対象の文字がなければ、タイトルを使います。短文や多言語文書では lang を明示してください

  • 右から左へ書く文書は dir: rtl、左から右なら dir: ltr を指定できます。auto は文書内容からブラウザーが判定し、lang や実行環境のロケールだけから方向を推測しません

  • lang の先頭の言語サブタグが ja なら、自動生成する日付は 2026 年 8 月 3 日 の形式、それ以外では 2026-08-03 の形式になります。フロントマターの date に書いた文字列は変更しません

2.2 複数ファイルの結合

ディレクトリーを入力にすると、直下の *.md がファイル名順に結合されます。

  • 各ファイルにフロントマターを書けます。ファイルの並び順でキーごとに最初に現れた値を文書全体に適用し、後続ファイルは未設定のキーを補います。先頭ファイルにフロントマターがなくても、後続ファイルで title を指定できます。既存の値を一時的に置き換えたい場合は、対応する CLI オプションを使って上書きします
  • どのファイルにも title が指定されていない場合だけ、H1 を探します。後続ファイルで指定した title は、先行ファイルの H1 より優先します。H1 もなければ、先頭ファイル名ではなく入力ディレクトリー名を使います
  • false も指定済みの値として扱います。bibliography のリストは一つの値として選び、後続ファイルのリストを連結しません
  • 値の採否にかかわらず全ファイルで YAML の構文と既知のキーの型・値を検査し、未知のキーには警告を出すか、--strict-front-matter でエラーにします。採用しない logo / bibliography は参照先の存在を確認せず、読み込みません。採用する相対パスの基準は、そのキーを最初に指定したファイルの親ディレクトリーです
  • 拡張子は小文字の .md だけが対象です
  • ファイルは UTF-8 で保存してください（先頭の BOM と CRLF 改行は受け付けます）
  • 各ファイルは独立した Markdown として解釈されます。コードフェンス、リスト、生の HTML ブロック、参照リンクの定義を次のファイルへ続けることはできません。これらの構文は各ファイル内で完結させてください

2.3 ファイル間のリンク

同じ文書に結合される Markdown ファイルへの相対リンクは、クエリー文字列を含まない場合に PDF 内へのリンクへ変換されます。フラグメントを省略すると、対象ファイルの先頭へ移動します。Markdown 記法と生の HTML の <a href> のどちらでも使えます。

詳細は [03 章](03_gfm.md) を参照してください。

別ファイル内の見出しへ直接移動するには、見出しの ID をフラグメント（URL の # 以降の部分）として付けます。文書内で同じ見出しが複数ある場合は、2 個目以降の ID に -2、-3 などが付きます。リンクには生成された実際の ID を指定してください。

[表の節](03_gfm.md#34-表)を参照してください。

見出しへの文書内リンクも使えます。

[フロントマターの節](#21-フロントマター) を参照してください。

クエリー文字列付きの相対リンク、結合対象外の .md や、.md 以外のローカルファイルへのリンクは書き換えず、レンダラーへ渡します。pfpdf はリンク先や指定したフラグメントの存在を検査しないため、PDF の閲覧環境で開ける参照先を用意してください。PDF の配布先でも開きたいファイルには HTTP(S) URL を使ってください。特定のコンピューター上のファイルを開く場合は、絶対 file: URL を指定できます。

2.4 目次と改ページ

  • 目次は既定で生成されます。通常はフロントマターの toc: false で無効化し、一時的な上書きには --toc / --no-toc を使います
  • PDF の栞は、目次と同じ見出しの階層で生成されます。toc: false で目次を省いても、栞は残ります
  • 改ページしたい位置には、単独の行に ___（アンダースコアを 3 個以上続けたもの）を書きます
ここで章が終わります。

___

ここから新しいページが始まります。

___ は pfpdf の拡張です。水平線を出したいときは --- または *** を使ってください。

改ページは次のブロックを新しいページから始めます。文書の先頭・末尾にある ___ は無視します。連続する ___ は 1 回の改ページにまとめ、空白ページは作りません。

2.5 画像などの相対パス

Markdown ファイルを入力にした場合は、その親ディレクトリーが相対パスの基準です。ディレクトリーを入力にした場合は入力ディレクトリーが基準になり、対象の Markdown ファイルはいずれもその直下にあります。

![構成図](assets/diagram.png)

一方、CLI 引数（--input、--output、--logo など）の相対パスは、pfpdf を実行したカレントディレクトリーが基準です。

Markdown、生の HTML、CSS に静的に書いたローカル URL は、参照関係を管理するリソースグラフを通じて解決されます。スクリプトが実行時に文字列から作るローカルパスは自動では公開されません。リソースは src / href / CSS の url() に静的に記述するか、HTTP(S) URL で指定してください。

文書内の URL でパスを区切る文字は、OS にかかわらず / です。Windows の絶対パスは file:///C:/docs/image.png、UNC パスは file://server/share/... のような有効な URL で書きます。CLI 引数のパスだけは、実行する OS の通常の表記を使えます。
